## T. Trappole / casi limite

1. **`timeout: 0` = CSR immediato + render in background.** Con strategia `DEFAULT` e `timeout` falsy, `shouldTimeout` è falso: ogni prima richiesta riceve CSR e il risultato SSR serve la richiesta successiva (anche con `cache:false`, una sola volta). È la modalità di `serve:ssr:ci`. — `core-libs/setup/ssr/optimized-engine/optimized-ssr-engine.ts:L187-L192`, `:L273-L279`, `:L296-L299`; `package.json:L154-L154`.
2. **`cache:false` non significa "nessuna memoria".** I render terminati dopo il fallback sono comunque salvati (soggetti a `cacheSizeMemory` e `shouldCacheRenderingResult`) finché una richiesta non li consuma; se nessuno richiede più quell'URL restano in memoria. — `core-libs/setup/ssr/optimized-engine/optimized-ssr-engine.ts:L296-L299`, `:L223-L226`; `core-libs/setup/ssr/optimized-engine/ssr-optimization-options.ts:L24-L31`.
3. **`ALWAYS_SSR` ignora concorrenza e render in corso.** Può superare `concurrency` e, senza `reuseCurrentRendering`, avviare un secondo render per la stessa chiave (che con `setAsRendering` sovrascrive il placeholder). Il resolver di default non restituisce mai `ALWAYS_SSR`: serve un resolver custom. — `core-libs/setup/ssr/optimized-engine/optimized-ssr-engine.ts:L153-L158`; `core-libs/setup/ssr/optimized-engine/rendering-strategy-resolver.ts:L62-L72`.
4. **`excludedUrls` sono RegExp/sottostringhe su `request.url`.** `'checkout'` esclude qualunque URL che contenga "checkout" (anche un prodotto con quello slug); caratteri speciali regex nelle voci cambiano il significato. — `core-libs/setup/ssr/optimized-engine/rendering-strategy-resolver.ts:L36-L38`.
5. **`cx-preview` sempre CSR** (SmartEdit), non disattivabile con le opzioni del resolver di default. — `core-libs/setup/ssr/optimized-engine/rendering-strategy-resolver.ts:L11-L13`, `:L65-L67`.
6. **Chiave di cache = origin + `originalUrl`.** Include host (da `Host` o `X-Forwarded-Host` fidato) e query string: varianti di query o host diversi generano entry distinte; Host header manipolati possono avvelenare la cache → motivo di `getOriginValidationMiddleware`. — `core-libs/setup/ssr/express-utils/express-request-url.ts:L10-L12`; `core-libs/setup/ssr/express-utils/express-origin-validation-middleware.ts:L14-L17`.
7. **Eviction FIFO che può rimuovere placeholder `rendering`.** `clearOldestEntriesForSize` prende la prima chiave della Map senza distinguere i placeholder `{rendering:true}` (dimensione 0): rimuoverne uno non libera spazio ma fa sì che `isRendering` diventi falso per un render ancora in corso (permettendo un render duplicato o un fallback diverso). Analisi statica. ⚠️ DA VERIFICARE con test. — `core-libs/setup/ssr/optimized-engine/rendering-cache/rendering-cache.ts:L31-L31`, `:L88-L103`.
8. **Nessun LRU.** `get` non riordina: una pagina molto richiesta viene sfrattata quanto una mai letta. — `core-libs/setup/ssr/optimized-engine/rendering-cache/rendering-cache.ts:L105-L107`.
9. **TTL lazy.** Entry scadute non vengono rimosse finché non vengono sovrascritte o sfrattate; continuano a occupare `usedSize`. — `core-libs/setup/ssr/optimized-engine/rendering-cache/rendering-cache.ts:L116-L127`.
10. **Errori non cachati di default anche per il "one-shot".** Con il default `!err`, un render tardivo in errore non viene conservato: la richiesta successiva rifà il render. — `core-libs/setup/ssr/optimized-engine/ssr-optimization-options.ts:L234-L234`; `core-libs/setup/ssr/optimized-engine/rendering-cache/rendering-cache.ts:L54-L61`.
11. **Opzioni di cache invalide solo loggate.** `cacheSizeMemory` ≤ 0 o calculator mancante producono un log d'errore, non un'eccezione; con limite 0 nessuna entry con dimensione > 0 viene mai salvata (neppure il one-shot). — `core-libs/setup/ssr/optimized-engine/rendering-cache/rendering-cache-size-manager.ts:L24-L54`, `:L74-L76`.
12. **Merge shallow delle opzioni.** Passare `logger: undefined` o `renderingStrategyResolver: undefined` esplicitamente sovrascrive il default: nel primo caso il costruttore lancia, nel secondo la strategia diventa `DEFAULT` (pagine checkout/my-account renderizzate in SSR). — `core-libs/setup/ssr/optimized-engine/optimized-ssr-engine.ts:L63-L78`, `:L118-L122`.
13. **`getLoggableSsrOptimizationOptions` con valori `null`.** `typeof null === 'object'` e `null.constructor` lancia TypeError: un'opzione impostata a `null` farebbe fallire il costruttore in `logOptions`. Analisi statica. — `core-libs/setup/ssr/optimized-engine/get-loggable-ssr-optimization-options.ts:L20-L23`, `:L37-L39`.
14. **`NgExpressEngineDecorator.get(engine)` ≠ `get(engine, null)`.** Senza secondo argomento si applica l'ottimizzazione con i default; solo `null` la disattiva. — `core-libs/setup/ssr/engine-decorator/ng-express-engine-decorator.ts:L53-L56`, `:L69-L72`.
15. **Senza `OptimizedSsrEngine` manca `EXPRESS_SERVER_LOGGER`.** L'unico provider è in `startRender`; con `optimizationOptions: null`, `ExpressLoggerService` (scelto perché `REQUEST` esiste) fa `inject(EXPRESS_SERVER_LOGGER)` non opzionale → probabile `NullInjectorError` alla prima risoluzione di `LoggerService`. ⚠️ DA VERIFICARE a runtime (niente `node_modules`). — `core-libs/setup/ssr/logger/services/express-logger.service.ts:L26-L27`; `core-libs/setup/ssr/logger/services/server-logger-service-factory.ts:L12-L17`; `core-libs/setup/ssr/optimized-engine/optimized-ssr-engine.ts:L426-L429`.
16. **`allowedHosts` non configurato → "SSR" che è in realtà CSR, potenzialmente cachato.** Senza `NG_ALLOWED_HOSTS` né `allowedHosts`, `CommonEngine.render` restituisce il documento grezzo come successo; per `OptimizedSsrEngine` è un HTML valido e, con `cache:true`, viene salvato e servito con status 200 senza `no-store`. La demo non passa `allowedHosts` e conta sulla env negli script npm. — `deps:angular-ssr-21.2.23/package/fesm2022/node.mjs:L117-L135`; `projects/storefrontapp/src/server.ts:L51-L56`; `package.json:L152-L155`.
17. **Incoerenza origin.** `ngExpressEngine` costruisce l'URL con `req.get('host')`, mentre la chiave di cache e `SERVER_REQUEST_ORIGIN` usano `getRequestOrigin` (che può preferire `X-Forwarded-Host`). — `core-libs/setup/ssr/engine/ng-express-engine.ts:L104-L106`; `core-libs/setup/ssr/express-utils/express-request-origin.ts:L12-L25`.
18. **Errori sincroni non-`Error` inghiottiti.** In `ngExpressEngine` un `throw` di un valore non `Error` non chiama il callback: il render resta "in corso" fino a `maxRenderTime` (e la richiesta attende il proprio timeout). — `core-libs/setup/ssr/engine/ng-express-engine.ts:L124-L126`.
19. **Concorrenza solo per-processo e senza abort.** `currentConcurrency` è un contatore in memoria per istanza; dopo `maxRenderTime` lo slot viene liberato ma il render continua a consumare memoria/CPU. — `core-libs/setup/ssr/optimized-engine/optimized-ssr-engine.ts:L38-L38`, `:L405-L417`.
20. **`maxRenderTime` < `timeout`.** Il JSDoc lo vieta; se accade, il render viene dichiarato hanging prima del timeout della richiesta e il suo esito ignorato, quindi il client riceve CSR solo allo scadere del proprio `timeout`. — `core-libs/setup/ssr/optimized-engine/ssr-optimization-options.ts:L104-L104`; `core-libs/setup/ssr/optimized-engine/optimized-ssr-engine.ts:L435-L442`.
21. **`reuseCurrentRendering` + `cache:false`: `store`/`clear` multipli sulla stessa chiave.** Le callback condivise vengono eseguite in sequenza: una richiesta già in CSR fa `store`, una ancora in attesa fa `clear` (o viceversa secondo l'ordine d'arrivo); l'esito in cache dipende dall'ordine. Analisi statica. — `core-libs/setup/ssr/optimized-engine/optimized-ssr-engine.ts:L282-L300`, `:L366-L368`.
22. **Log "waiting" fuorviante.** Con reuse attivo anche la richiesta che avvia il render logga "Request is waiting..."; e i log del render (`Rendering started/completed`) portano il contesto della prima richiesta. — `core-libs/setup/ssr/optimized-engine/optimized-ssr-engine.ts:L374-L377`, `:L419-L419`.
23. **`traceparent` malformato produce un log `error` per ogni richiesta** ma non blocca il rendering. — `core-libs/setup/ssr/optimized-engine/request-context.ts:L94-L102`.
24. **Fallback CSR e template dal filesystem in modo sincrono** (solo la prima volta per path): nessuna invalidazione se il file cambia a caldo. — `core-libs/setup/ssr/optimized-engine/optimized-ssr-engine.ts:L311-L320`.
25. **`defaultExpressErrorHandlers` non chiama `next`** e non logga: se gli header sono già inviati l'errore sparisce silenziosamente. — `core-libs/setup/ssr/error-handling/express-error-handlers/express-error-handlers.ts:L23-L31`.
26. **Wildcard origin:** `*` non copre l'apex né più livelli (`a.b.my.domain.com` non è ammesso da `https://*.my.domain.com`). — `core-libs/setup/ssr/express-utils/express-origin-validation-middleware.ts:L32-L36`, `:L89-L95`.
27. **`DefaultExpressServerLogger` dev/prod dipende da `ngDevMode` a livello di processo Node**, non dall'app: nel bundle server ottimizzato (`ngDevMode` false) i log sono JSON a riga singola. ⚠️ DA VERIFICARE che il build server definisca `ngDevMode=false` (dipende dalla config del builder). — `core-libs/setup/ssr/logger/loggers/default-express-server-logger.ts:L69-L73`; `angular:packages/core/src/util/is_dev_mode.ts:L20-L22`.
