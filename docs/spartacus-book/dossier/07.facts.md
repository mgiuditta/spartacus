## T. Trappole / casi limite

- T1. Spartacus usa `initialNavigation: 'enabledBlocking'` (`core-libs/storefront/router/app-routing.module.ts:L17-L17`) e la demo abilita `provideClientHydration` (`projects/storefrontapp/src/app/app.config.ts:L29-L29`): da codice Angular, in dev mode `provideEnabledBlockingInitialNavigationDetector` emette il warning "found both hydration and enabledBlocking initial navigation … contradiction" (`angular:packages/platform-browser/src/hydration.ts:L152-L174`; `angular:packages/router/src/router_module.ts:L237-L244`). ⚠️ DA VERIFICARE a runtime (impossibile eseguire: niente node_modules).
- T2. Il meta-reducer browser NON applica lo state trasferito se in storage c'è un `access_token` (`core-libs/core/src/state/reducers/transfer-state.reducer.ts:L81-L81`; `auth-state-persistence.service.ts:L119-L121`): per utenti loggati il client ricarica i dati.
- T3. Il meta-reducer browser agisce solo su `action.type === INIT` (`transfer-state.reducer.ts:L76-L76`): chiavi di feature registrate dopo INIT dipendono da come NgRx gestisce chiavi sconosciute nello state root (⚠️ vedi Q2).
- T4. Il meta-reducer server ricalcola e riscrive `cx-state` a ogni azione (`transfer-state.reducer.ts:L51-L61`): costo proporzionale al numero di azioni durante il render; vince l'ultimo state prima di `BEFORE_APP_SERIALIZED`.
