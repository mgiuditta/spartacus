## T. Trappole / casi limite
- T1. Gli APP_INITIALIZER di language/currency/baseSite NON restituiscono la Promise di `initialize()` (`() => void`): Angular non li attende; il bootstrap è bloccato solo dall'APP_INITIALIZER `initializeContext` (`getStable('context')`), non dall'impostazione dei valori attivi. — `core-libs/core/src/site-context/providers/context-initializer-providers.ts:L15-L17`, `angular:packages/core/src/application/application_init.ts:L246-L256`.
- T2. Anche `initializeTheme`, `onNavigateFactory`, `addCmsRoute`, `initConfigurableRoutes`, `htmlLangProvider` e il validator sono sincroni / ritornano `void`. — `site-theme-initializer-providers.ts:L12-L14`, `app-routing.module.ts:L35-L36`, `add-cms-route.ts:L19-L23`, `routing.module.ts:L40-L41`, `html-lang-provider.ts:L24-L29`, `config-validator.module.ts:L28-L36`.
- T3. `initConfigurableRoutes` legge `routing.routes` sincronamente durante `runInitializers`, quindi usa la config statica: eventuali contributi asincroni allo scope `routing` di un CONFIG_INITIALIZER (es. secure portal) non sono garantiti come già applicati alle `Route`. ⚠️ DA VERIFICARE: non ho verificato se `SecurePortalConfigInitializer` contribuisca `routing.routes` o solo `routing.protected`. — `core-libs/core/src/routing/routing.module.ts:L93-L95`, `routing-config.service.ts:L26-L27`.
- T4. Se un `configFactory()` di CONFIG_INITIALIZER rigetta, `finishScopes` non viene chiamato: `initialize()` rigetta (quindi l'APP_INITIALIZER e il bootstrap falliscono via `this.reject(e)`), e ogni `getStable` sullo scope resta in attesa. — `config-initializer.service.ts:L156-L174`, `angular:packages/core/src/application/application_init.ts:L266-L269`.
- T5. `SiteContextConfigInitializer` lancia se l'URL non matcha nessun `urlPatterns` dei base site ⇒ bootstrap fallito quando `context.baseSite` non è configurato staticamente. — `site-context-config-initializer.ts:L65-L69`.
- T6. Il caricamento della config `context` dal backend è disattivato appena `context.baseSite` è presente staticamente (come nell'app demo): in quel caso language/currency/urlParameters non arrivano dal backend. — `site-context.module.ts:L37-L40`, `spartacus-b2c-configuration.providers.ts:L26-L31`.
- T7. `CONFIG_INITIALIZER` senza `scopes` (o con array vuoto) lancia `Error('CONFIG_INITIALIZER should provide scope!')`, mentre scope sovrapposti producono solo un warning in dev mode. — `config-initializer.service.ts:L144-L152`.

- T9. `finishScopes` usa `splice(newScopes.indexOf(scope), 1)`: se lo scope non fosse presente (`-1`) rimuoverebbe l'ultimo elemento. In pratica gli scope sono sempre stati aggiunti in `initialize`. — `config-initializer.service.ts:L77-L83`.
