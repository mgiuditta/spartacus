## P1 [impreciso] — sezione 3.7, punto 4 (e §9.6)
- Testo nel capitolo: "applica il reducer interno per id; solo risultati truthy entrano negli update e lo stato cambia riferimento solo se c'è almeno un update"
- Problema: il testo è letterale ma porta fuori strada. Un "update" è qualunque risultato truthy, anche quando è lo stesso oggetto di prima. Con `entityLoaderReducer` ed `entityProcessesLoaderReducer` il reducer interno (`loaderReducer` o `processesLoaderReducer`) restituisce `state` per le azioni non pertinenti. Si finisce nel ramo `else` (tutte le chiavi), `entityUpdates` non è vuoto e il reducer restituisce un nuovo oggetto `{...state, entities: {...}}`. Quindi, se esiste almeno un'entità, slice come `process` o `cart.carts` cambiano riferimento a **ogni** azione dispatchata nell'app. È una conseguenza importante per §9.6 (non solo O(n), anche nuova referenza a ogni azione) e per §9.18 (`combineReducers` vede "un cambiamento" a ogni azione).
- Correzione: "applica il reducer interno per id; ogni risultato truthy, anche se identico allo stato precedente, entra negli update. Con un reducer interno di tipo loader, se esiste almeno un'entità, lo stato cambia riferimento a ogni azione." — `core-libs/core/src/state/utils/entity/entity.reducer.ts:L42-L44`, `:L53-L63`: `ids = Object.keys(state.entities);` … `if (newState) { entityUpdates[id] = newState; }` … `if (Object.keys(entityUpdates).length > 0) { return { ...state, entities: { ...state.entities, ...entityUpdates }, };`; `core-libs/core/src/state/utils/loader/loader.reducer.ts:L72-L78`: `if (reducer) { … } return state;`
