## P4 [falso] — sezione 8.2 (esempio)
- Testo nel capitolo: "`protected isDataLoaded(): Observable<boolean> { return inject(ActiveCartFacade).isStable(); // qualsiasi Observable<boolean> }`"
- Problema: `isDataLoaded()` non gira in un injection context. Viene invocato dentro lo `switchMap` di `qsi$`, quando arriva l'evento `qsi_js_loaded`. Lì `inject()` lancia `NG0203` ("`inject()` function must be called from an injection context …"). L'esempio così com'è non funziona.
- Correzione: ottenere la dipendenza in un field initializer (o nel costruttore) e usarla nel metodo, per esempio:
  ```ts
  export class MyQualtricsLoaderService extends QualtricsLoaderService {
    protected activeCart = inject(ActiveCartFacade);
    protected isDataLoaded(): Observable<boolean> {
      return this.activeCart.isStable();
    }
  }
  ```
  — `feature-libs/qualtrics/components/qualtrics-loader/qualtrics-loader.service.ts:L66-L67` ("protected qsi$: Observable<any> = this.qsiLoaded$.pipe( switchMap(() => this.isDataLoaded()),"), `angular:packages/core/src/di/injector_compatibility.ts:L97-L105` ("const currentInjector = getCurrentInjector(); if (currentInjector === undefined) { throw new RuntimeError( RuntimeErrorCode.MISSING_INJECTION_CONTEXT, … `inject()` function must be called from an injection context …"), `feature-libs/cart/base/root/facade/active-cart.facade.ts:L91-L91` ("abstract isStable(): Observable<boolean>;").

## P6 [impreciso] — sezione 8.1 (esempio)
- Testo nel capitolo: "`@Injectable({ providedIn: 'root' }) // obbligatorio: TmsService usa l'injector root (T3)`"
- Problema: `providedIn: 'root'` non è obbligatorio. Basta che il collector sia risolvibile dall'injector iniettato in `TmsService`, cioè l'injector root dell'app. Va bene anche un provider nei `providers` dell'`AppModule` o di un NgModule importato eagerly, perché l'injector del modulo raccoglie i provider di tutti i moduli importati. È escluso solo il caso di un provider presente unicamente in un modulo lazy, come dice T3. Q4 ("deve essere disponibile nel root injector") è invece formulata correttamente.
- Correzione: "`@Injectable({ providedIn: 'root' }) // oppure fornito nei providers di un modulo eager: TmsService lo risolve dall'injector root (T3)`" — `feature-libs/tracking/tms/core/services/tms.service.ts:L27-L41` ("@Injectable({ providedIn: 'root' }) export class TmsService … protected injector: Injector"), `feature-libs/tracking/tms/core/services/tms.service.ts:L71-L73` ("const collector = this.injector.get<TmsCollector>( collectorConfig.collector );"), `angular:packages/core/src/di/create_injector.ts:L49-L55` ("const providers = [additionalProviders || EMPTY_ARRAY, importProvidersFrom(defType)]; … return new R3Injector(providers, …").

## P7 [impreciso] — sezione 3.5, passo 5 (e T21)
- Testo nel capitolo: "`ScriptLoader` mette in `setAttribute` solo le chiavi che iniziano con `data-`; le altre (qui `id`) diventano proprietà del DOM element"
- Problema: la regola ha un'eccezione. Con `disableKeyRestriction: true`, anche le chiavi che non sono proprietà dell'elemento `<script>` passano per `setAttribute`. Nel caso SmartEdit l'opzione non è passata, quindi la conclusione su `id` resta corretta, ma la regola generale è enunciata in modo assoluto.
- Correzione: "`ScriptLoader` usa `setAttribute` per le chiavi che iniziano con `data-` (e, solo con `disableKeyRestriction`, per quelle che non sono proprietà dello `<script>`); le altre diventano proprietà del DOM element. SmartEdit non passa `disableKeyRestriction`, quindi `id` diventa `script.id`." — `core-libs/core/src/util/script-loader.service.ts:L70-L80` ("if ( key.startsWith('data-') || (disableKeyRestriction && !(key in script)) ) { script.setAttribute(key, attributes[key as keyof object]); } else { (script as any)[key] = attributes[key as keyof object]; }")
