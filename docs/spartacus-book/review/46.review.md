## P1 [falso] — sezione 3.5, punto 2
- Testo nel capitolo: "il buffer vive nella closure creata per ogni subscription (`core-libs/core/src/util/rxjs/buffer-debounce-time.ts:L10-L24`)"
- Problema: `bufferedValues` viene dichiarato dentro la funzione `(source) => { ... }`, cioè l'`OperatorFunction`. Questa gira quando l'operatore viene applicato (`pipe(...)`), non a ogni subscription. Non c'è nessun `defer`. Più subscription allo stesso Observable già "pipato" condividono quindi lo stesso buffer. Negli effect attuali questo non dà problemi, perché l'operatore viene applicato dentro una funzione che riceve `debounce` e `scheduler` e ogni stream ha una sola subscription, ma l'affermazione resta sbagliata.
- Correzione: "il buffer vive nella closure creata ogni volta che l'operatore viene applicato a una sorgente (al momento del `pipe`, non della subscription): due subscription allo stesso Observable risultante condividerebbero il buffer" — `core-libs/core/src/util/rxjs/buffer-debounce-time.ts:L14-L22`:
  ```ts
    return (source: Observable<T>) => {
      let bufferedValues: T[] = [];

      return source.pipe(
        tap((value) => bufferedValues.push(value)),
        debounceTime(time, scheduler),
        map(() => bufferedValues),
        tap(() => (bufferedValues = []))
      );
  ```
