## P2 [falso] — sezione 9, trappola 3 (e §3.4 punto 4)
- Testo nel capitolo: "**Mescolare multi e non-multi.** Angular lancia solo in dev mode; in produzione l'ultimo `records.set` sovrascrive silenziosamente."
- Problema: vale solo in un verso. Se un provider **non-multi** arriva dopo uno multi, in produzione `records.set(token, record)` sovrascrive davvero senza errori. Se invece un provider **multi** arriva dopo un non-multi sullo stesso token, `multiRecord` è il record non-multi (con `multi === undefined`). Senza `ngDevMode` il controllo viene saltato e `multiRecord.multi!.push(provider)` lancia un `TypeError` (lettura di `push` su `undefined`) mentre si costruisce l'injector. In produzione un non-multi dopo un multi sovrascrive silenziosamente il record; un multi dopo un non-multi fa fallire la creazione dell'injector con un `TypeError` (`multiRecord.multi` è `undefined`)" — `angular:packages/core/src/di/r3_injector.ts:L500-L512` (`let multiRecord = this.records.get(token); if (multiRecord) { if (ngDevMode && multiRecord.multi === undefined) { throwMixedMultiProviderError(); } } ... multiRecord.multi!.push(provider);`), `angular:packages/core/src/di/r3_injector.ts:L692-L702` (`multi: multi ? ## P3 [impreciso] — sezione 3.4 (dedup dei moduli), riflesso in trappola 13
