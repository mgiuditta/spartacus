## P7 [impreciso] — sezione 8, esempio illustrativo (`renderKeyResolver`)
- Testo nel capitolo: "ignorare un parametro di tracking nella chiave" con `getDefaultRenderKey(req).replace(/([?&])utm_[^&]*&?/g, '$1')`.
- Problema: la regex lascia separatori pendenti. `https://h/p?utm_a=1` diventa `https://h/p?` e `https://h/p?x=2&utm_a=1` diventa `https://h/p?x=2&`. Le chiavi restano diverse da `https://h/p` e `https://h/p?x=2`, quindi l'obiettivo dichiarato (stessa entry di cache con o senza parametro di tracking) non viene raggiunto in tutti i casi. È un esempio illustrativo, non codice del repo, ma va presentato come funzionante o corretto.
- Correzione: usare per esempio `new URL(getDefaultRenderKey(req))`, eliminare i parametri `utm_*` da `searchParams` e restituire `url.toString()`. In alternativa, segnalare nel commento che la regex è solo indicativa. La chiave di default resta `getRequestOrigin(req) + req.originalUrl` (`core-libs/setup/ssr/express-utils/express-request-url.ts:L10-L12`):
  ```ts
  export function getRequestUrl(req: Request): string {
    return getRequestOrigin(req) + req.originalUrl;
  }
  ```
